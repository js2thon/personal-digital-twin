# Decision & Authorization Specification（摘要）

## 1. 决策权限四级模型
| 级别 | 能力 | MVP |
|---|---|---|
| D0 | 分析信息 | 允许 |
| D1 | 生成决策建议 | 允许 |
| D2 | 提交人工审批 | 允许 |
| D3 | 自动执行 | **禁止** |

## 2. 决策流程
解析业务上下文 → 检索个人知识/历史决策/认知模型 → 证据充分性判断（不足 → needs_info）→ LLM 决策分析 → 确定性规则检查（如预算 > 50 万必须人工审批）→ 风险与权限评估 → 人工审批 → 执行前最终校验 → 执行 → 结果验证 → 保存决策与审计。

## 3. 硬性规则
- 证据不足时 recommendation 必须为 needs_info，不得臆测。
- 数字分身不得自动创造本人没有表达过的承诺、立场、报价、时间节点和授权。
- 高风险（risk_level=high）直接 denied，不进入审批流。
- 执行前重新验证：授权是否有效、业务对象是否变化、操作是否重复。

## 4. 未来开放 D3 的条件
- 影子测试通过：在历史决策案例上一致性、证据质量和安全指标达标。
- 按动作逐项授权（workflow.action_authorizations），带 scope / max_amount / requires_confirmation / expires_at。
- 到期自动失效，未登记动作一律拒绝。

## 5. 审计要求
每次决策保存不可变快照（含输入、证据、Profile 版本、模型与 Prompt 版本、建议），带哈希防篡改；记录审批人、执行结果。审计日志限制读取并脱敏。
